# P0 文档 v3 改动摘要（2026-10-31）

> 本文件只记录 **v2 → v3** 的 6 条变更。v2 的内容（取消签名、逐项授权、v3 页面模型、
> 24 项权限目录等）不在这里重复，见 `P0-V2-CHANGELOG.md`。
> 本文不替代契约文档；有冲突时以 `PLUGIN-SECURITY.md` / `PLUGIN-SYSTEM.md` /
> `plugin.schema.json` 为准。
>
> **本版不动业务代码，不改 `plugin.schema.json`**（权限枚举 24 项未变）。

## 一、这版改了什么（一句话）

**critical 授权从「绑定包哈希」改为「绑定权限集 + 哈希白名单」** —— 更新内容不再让用户重走 30 次确认；
顺带补上取证用的来源字段、24 项权限的人话后果对照表、**P1 的最小崩溃闭环**、
安装页权限按后果分 5 组、以及 JSON 插件的表达力上限。

| # | 变更 | 一句话 |
|---|---|---|
| 1 | critical 授权改为权限集绑定 | 包哈希变、权限集不变 ⇒ **不重确认**；`approvedHashes` 只记同意过的内容，最多 5 个 |
| 2 | registry 新增 `source` 取证字段 | `local-import` / `url` / `share-sheet` / `dev-dir` + `sourceDetail` + `installedAt`；管理页只写事实 |
| 3 | 「等价后果翻译」对照表 | 24 项权限各一句人话；安装页**必须**显示这句话而不是权限 id |
| 4 | P1 加最小崩溃闭环 | 连续 3 次未跨过首帧 ⇒ 自动停用最近启用的插件并提示；完整安全模式仍留 P2 |
| 5 | 权限分组展示 | 5 个后果组、默认折叠、组标题写后果；critical 仍逐项确认 |
| 6 | JSON 插件的表达力上限 | 静态展示 / 声明式动作 / 静态过滤能做；计算 / 循环 / 异步 / 状态机必须 `js` |

## 二、逐条明细

### 变更 1：critical 授权不再按包哈希强行重确认

**改了什么**

- critical 授权**主键**固定为 `(pluginId, permissionId)`，不再含 `packageHash`。
- registry 新增 `approvedHashes: [sha256…]`，**最多保留最近 5 个**（新值前插，超出丢最旧）。
  它**不授予任何权限**，只用于更新页展示、管理页取证、崩溃报告关联；清空它不影响授权有效性。
- registry 新增 `permissionSet`（上一版 manifest 的规范化权限集，`id:risk` 按 id 排序拼接）。
  升级时用它判断「权限集是否变了」，无需依赖旧版本目录还在。
- 判定表（`PLUGIN-SECURITY.md` 3.4）：包哈希变 + 权限集不变 ⇒ **不重确认**，更新页显示
  「内容已更新，权限未变」；新增 / 变更 critical（含中→critical）⇒ 只为涉及项走三次确认；
  `major` 变化 ⇒ 全部 critical 重走三次确认。
- **权限集缩小 ⇒ 自动撤销多余项，不弹窗**，只写一条诊断日志。
- `criticalGrants` 里**删除** `packageHash` 字段，改为记 `majorVersion`。

**改了哪个文件**

|---|---|---|
| `PLUGIN-SECURITY.md` | 文首 v3 说明 | 新增 v3 变更段 |
| | 3.1 三种默认状态表 | critical 行改为「按权限集沿用」 |
| | 3.3 第 3 次确认正文 / 计时硬规则表「重复」「记录」两行 | 文案与判定改为权限集语义 |
| | **3.4 授权绑定与失效**（整节重写） | 新主键、`approvedHashes`、「更新时到底要不要重确认」判定表、8 条补充规则 |
| | 5.1 `packageHash` 用途 | 去掉「授权绑定」，改为取证用途 |
| | 8.1 验收 5～11 条 | 新增权限集 / major / 缩权 / 哈希白名单的验收项 |
| `PLUGIN-SYSTEM.md` | 文首 v3 说明 | 新增 v3 变更段 |
| | 4.5 升级表「同 id 高版本」 | critical 改为按权限集沿用 |

| `PLUGIN-AUTHORING.md` | 3.3 / 9.2 | 告知作者「绑定权限、不绑定字节」，并说明不要为凑重审而加权限或抬 major |
| `DECISIONS.md` | 新增 **ADR-024** | 决策、理由、后果与残余风险 |

**对 P1 的影响**

- registry 第一版就要有 `approvedHashes` 与 `permissionSet` 字段（P1 = 注册表落地期，迁移成本最低）。
- 安装器 / 更新流程必须实现「权限集比对」这一步，不能再写成「哈希不等 ⇒ 全部失效」。
- 更新页要有一条「内容已更新，权限未变」的文案分支。
- 工作量增量：约 1 个判定函数 + 1 个文案分支 + 2 个新字段；**不涉及 UI 大改**。

### 变更 2：新增来源字段（取证最低线）

**改了什么**

- `source` 结构改为：`kind` ∈ {`local-import`, `url`, `share-sheet`, `dev-dir`}、
  `sourceDetail`（域名或文件名，可空）、`installedAt`（本次安装时间）。
  旧的 `kind: "file" | "url" | "dev"` + `displayName` 保留映射（见 `PLUGIN-SYSTEM.md` 6.2）。
- 插件级 `installedAt` 仍是「首次安装时间」；两者都保留，语义不同。
- 管理页显示**来源事实文本**：`从本地文件导入（hello.air2plugin）` /
  `从网址安装（example.com）` / `从分享面板导入（telegram）` / `开发目录（~/Dev/hello）`。
- **不做好坏判断、不挂任何徽标、不加颜色**，不出现「可信 / 未验证 / 未知来源 / 危险」等评价词。

**改了哪个文件**

| 文件 | 位置 | 改动 |
|---|---|---|
| `PLUGIN-SYSTEM.md` | 第六节 registry 示例 + 字段表 `source` / `installedAt` 行 | 新枚举、`sourceDetail`、`installedAt` |
| | 6.1 写入规则 | `source.kind` 枚举校验、`source.installedAt` 非空 |
| | 6.2 迁移 | 旧 kind 映射表 |
| `PLUGIN-SECURITY.md` | 3.5 管理页必须显示什么 | 来源事实文本的四种写法 + 禁止评价词 / 徽标 |
| | 8.1.1 展示与来源 第 18 条 | 验收项 |
| `DECISIONS.md` | ADR-024 决策 7 | 来源只写事实的原则 |

**对 P1 的影响**

- 导入路径有四种（文件选择器 / URL / 分享面板 / 开发目录），P1 至少实现前三种的 `kind` 记录；
  `dev-dir` 随 P4 开发模式落地，但**枚举值现在就要固定**，避免以后改注册表结构。
- 管理页最小版就要显示一行来源文本；不需要做任何评分 / 徽标逻辑（**明确禁止**）。
- 工作量增量：极小（写入时多两个字段，展示一行文本）。

### 变更 3：新增「等价后果翻译」对照表

**改了什么**

- `PLUGIN-SECURITY.md` 新增**第九节**：表头 `权限 id | 人话后果 | 展示位置`，覆盖全部 24 项
  （10 critical + 11 中 + 3 低），并给出 7 条措辞规则（只写行为不写评价、写后果不写机制、
  「等同代码执行」只用于 critical、中风险必须写清边界、每条 ≤ 30 汉字等）。
- **硬要求**：安装页 / 三次确认页 / 更新页 / 管理页 / 组合提示里，凡出现权限处**必须显示这句人话**，
  权限 id 只能作为可展开的次要信息。
- 示例：`files.game.write.content` →「能修改游戏内容（等同直接安装 mod，可执行代码）」；
  `launch.args` →「能改启动参数（可注入 javaagent）」；
  `launch.classpath` →「能替换游戏的 classpath（可注入代码）」；
  `java.agent` →「能向游戏进程注入 Java agent（等同任意代码执行）」；
  `native.module` →「能加载原生动态库（等同任意代码执行）」；
  `network.http` →「能联网（仅限声明过的域名）」。

**改了哪个文件**

| 文件 | 位置 | 改动 |
|---|---|---|
| `PLUGIN-SECURITY.md` | **第九节（新增）** | 24 项对照表 + 9.1 措辞规则 + 四处同步约束 |
| | 3.2 安装详情页 mockup | 权限行示例换成人话后果 |
| | 3.2 规则第 3 条 | 「必须显示人话后果，id 折叠」 |
| | 8.1.1 第 16、17 条 | 验收项（页面源码里不允许「只有 id 没有后果」的行） |
| | 第二节 | 权限目录与对照表的一致性约束（新增 id 必须同时补表） |
| `PLUGIN-AUTHORING.md` | 9.3 | 告知作者「组内逐条显示人话后果」 |

**对 P1 的影响**

- P1 的安装页 / 审查页需要一份**本地化字符串表**（24 条），不要写死在 UI 代码里。
- 英文版文案可以在 P1 用中文占位，但键必须一次定好（`perm.<id>.consequence`）。
- 工作量增量：24 条文案 + 1 张查表函数；**没有逻辑风险**。

### 变更 4：P1 加最小崩溃闭环

**改了什么**

- `suspectCount` 阈值统一为 **3**：`PLUGIN-SECURITY.md` 6.3 的升级路径表重写为
  「1 / 2 只记录（2 时管理页标 2/3）→ 3 自动停用最近启用的插件并提示 → 4+ 不再自动动作」。
- **P1 就实现**第 3 档：连续 3 次都死在首帧之前 ⇒ 停用「最近启用的插件」
  （`autoDisabled=true`，与用户手动停用区分）并给出可见提示。计数器不清零，`userSeq` 不变。
- 完整安全模式（禁全部 L2、再失败禁 L1）、逐插件诊断页、逐个恢复流程**仍留 P2**。
- 阈值从 2 提到 3 的理由：`suspectCount` 会因用户主动强杀 +1，「一次强杀 + 一次偶发失败」
  就停用插件会冤枉正常插件。

**改了哪个文件**

| 文件 | 位置 | 改动 |
|---|---|---|
| `PLUGIN-SECURITY.md` | 6.3 升级路径表 | 重写为 P1 / P2 两列，阈值 2 → 3 |
| | 6.4 P1 的实现范围 | 从「只计数、不自动禁用」改为「必须做自动停用」+ 为什么不能推到 P2 |
| | 8.4 验收 24～26 条 | 两次只记录、三次自动停用、四次起不再自动动作 |
| `PLUGIN-SYSTEM.md` | 第七节里程碑 P1 / P2 行 | P1 加「最小崩溃闭环」，P2 改「完整安全模式」 |

**对 P1 的影响**

- P1 必须实现：`autoDisabled` 字段、`lastEnabledChangeAt` 排序、自动停用的 UI 提示、
  「恢复被自动停用的插件」入口（否则用户只能重装）。
- 这是本版**唯一增加 P1 实现工作量**的变更（约 0.5～1 人日），但换来的是「坏插件不会把
  启动器锁死在崩溃循环里」——没有这条，P1 交付的插件系统是不可用的。

### 变更 5：权限分组展示

**改了什么**

- `PLUGIN-SECURITY.md` 新增 **3.2.1 权限分组展示**：24 项权限按**后果**归为 5 组
  （改游戏文件 / 联网 / 读你的数据 / 启动参数 / 改界面），**全覆盖且互斥**（3 + 4 + 2 + 10 + 5 = 24）。
- 组**默认折叠**，折叠态显示项数与最高风险级，含 critical 的组显示「含 N 项高危」；
  组标题**写后果**（「能修改游戏内容」「能改游戏如何启动」），不写权限分类名。
- 分组只影响展示：**critical 仍逐项三次确认**，不提供「整组授权」「一键全给」。
- `PLUGIN-AUTHORING.md` 新增 **9.3 权限会怎么分组显示**，告诉作者组标题不是他起的名字。

**改了哪个文件**

| 文件 | 位置 | 改动 |
|---|---|---|
| `PLUGIN-SECURITY.md` | **3.2.1（新增）** | 5 组映射表 + 7 条规则 |
| | 3.2 mockup + 规则 | 权限区改为折叠分组示例 |
| | 3.5 管理页 | 「按 5 组折叠展示，折叠态显示含 N 项高危」 |
| | 8.1.1 第 16 条 | 验收项 |
| `PLUGIN-AUTHORING.md` | **9.3（新增）** | 分组表 + 对作者的 4 条影响 |

**对 P1 的影响**

- 最小管理页 / 安装页需要一个固定的分组映射（本地常量表即可），**不要**从 manifest 推导。
- 折叠交互在 P1 可以是「一组一行 + 点开」，不需要复杂动画。
- 工作量增量：1 张静态映射表 + 折叠容器。

### 变更 6：明确纯 JSON 插件的表达力上限

**改了什么**

- `PLUGIN-AUTHORING.md` 新增**第五节「JSON 插件能做到什么 / 做不到什么」**：
  - 能做到：静态展示（slot / 主题 / 静态页面树）、声明式动作（只能用 `host.close` /
    `host.openPage` / `host.showOriginal` / `host.retry` / `host.copy`）、静态过滤、版本装饰、
    静态下载源、多语言、字面量。
  - 做不到：动态计算、循环、异步、状态机、按数据条件显隐、读宿主数据（纯 JSON 页面的
    `binding` 恒为空值）、读写文件 / 改启动参数 / 网络、HTML / 脚本 / WebView。
  - 给出「一句话判据」与 3 个「选错类型」的症状，并说明正确拆法是「静态留 JSON、计算放 JS」。
- 原第五～十二节顺延为六～十三节（内部「见第 X 节」引用同步修正）。

**改了哪个文件**

| 文件 | 位置 | 改动 |
|---|---|---|
| `PLUGIN-AUTHORING.md` | **第五节（新增）** | 5.1 能做到 / 5.2 做不到 / 5.3 选错类型 |
| | 3.3 末尾 | 指向第五节 |
| | 原文 §五～§十二 | 顺延为 §六～§十三；交叉引用「见第六节」→「见第七节」 |

**对 P1 的影响**

- **无**。P1 不支持 `type: js`（`E_TYPE_UNSUPPORTED`），纯 JSON 插件的能力上限在 P1 就是全部能力。
- 这条主要是**减少 P2 的返工**：作者按「JSON 全都能做」写的插件，到 P3 才发现要重写。

## 四、P1 开工前必须对齐的 5 件事

1. registry 结构一次写对：`approvedHashes`（≤5）、`permissionSet`、`source{kind,sourceDetail,installedAt}`。
2. 授权失效判定只用「权限集 + major」，**不要**再写「哈希不等 ⇒ 失效」。
3. 权限文案表（24 条人话后果）独立成本地化键，UI 只查表。
4. 安装页权限区一开始就按 5 组折叠，不要先平铺再改。
5. `suspectCount` 阈值 = 3，第 3 次自动停用最近启用的插件并提示（不能只计数）。
