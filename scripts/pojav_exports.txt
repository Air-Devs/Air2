# 主可执行文件的导出符号白名单
#
# Java 侧 GLFW.java 通过
#     new MacOSXLibraryDL(<主可执行文件名>, RTLD_DEFAULT)
# 从宿主可执行文件的【动态符号表】里解析 pojav* 系列 GLFW 桥接符号：
#     Init          = apiGetFunctionAddress(GLFW, "pojavInit")
#     CreateContext = apiGetFunctionAddress(GLFW, "pojavCreateContext")
#     ...
#
# 这些符号由 Air2/Player/Renderer/egl_bridge.m 定义。它们是普通的 C 全局符号，
# 默认【不进入】动态符号表（ld 默认隐藏未在 exported_symbols_list 里点名的符号），
# 于是 apiGetFunctionAddress 拿到 NULL，LWJGL 初始化直接抛：
#     java.lang.NullPointerException: A required function is missing: pojavInit
#     at org.lwjgl.glfw.GLFW$Functions.<clinit>
#     at org.lwjgl.glfw.GLFW.glfwInit
#     at com.mojang.blaze3d.platform.GLX._initGlfw
# 上机日志已实锤。
#
# 用 -Wl,-exported_symbols_list 点名导出（上游 Amethyst 用的是同一手法：
# -Wl,-exported_symbols_list,$(WORKINGDIR)/xxx.exports）。
#
# ⚠️ 不要改成 -export_dynamic：那会把【所有】全局符号一并导出，
# 包括 shaderc_impl_glue.c 引用的 glslang 运行期符号，dyld 会在启动阶段
# 强制解析它们，找不到就报
#     symbol not found in flat namespace '_glslang_finalize_process'
# 直接闪退（这个坑我们已经踩过一次）。
#
# 清单里写的是链接器用的名字，带前导下划线。
